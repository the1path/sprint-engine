# SE-025.1 — Shared website navigation

The built-in Sprint Runner and My Sprints Dashboard use one component for
navigation to the WordPress homepage. It prints a linked organisation image
when one is configured, and a centred **Back to website** link after `main`
regardless of branding. Both links use escaped `home_url( '/' )` and normal
same-tab navigation. They do not save Workspace drafts or write progress.

## Core presentation API

`ThePath\SprintEngine\Presentation\WebsiteNavigation` is an optional
presentation component for standalone templates:

- `enqueue_style()` enqueues its fingerprinted stylesheet. Call this during
  the standalone page's existing frontend enqueue callback.
- `logo()` prints the escaped linked image using `RunnerBranding::logo()`.
  It prints nothing when the branding helper has no image.
- `footer()` prints the labelled, underlined footer link, with a decorative
  arrow hidden from assistive technology. Call it after the primary content.

The component inherits the page's typography and uses `--se-muted`. Page CSS
still owns logo sizing, alignment and surrounding layout. There is no global
injection or new hook. Template overrides own their markup. Consumers that
support older builds must check for callable methods rather than infer their
presence from the version number. The branding helper itself is unchanged.

## Route inventory

The route and template audit covered Core Runner, Step Preview and Dashboard;
Pro My Journeys, Sprint History, Workbook and Journey Hub; the shared member
navigation and History partials; and the Pro Directory shortcode. The History
listing, Sprint detail and Workbook all use one template. Journey Continue
renders the Hub error template when unavailable; successful Continue requests
redirect and have no page markup. Login redirects also have no page markup.

Administrator Step Preview still displays the unlinked image. The branding
preview, admin/editor, REST/AJAX, successful Excel downloads and theme-embedded
Directory are excluded. Workbook print hides website links. Journey Hub keeps
its pre-existing brand link, including its site title or “Home” fallback.

## Verification

- Core: all 19 Composer test scripts with fresh disposable databases; PHP
  lint, PHPCS, Composer validation, JavaScript syntax and 39 tests; 69-file
  runtime ZIP and 45 metadata checks. Runner and Dashboard HTTP and Chromium
  suites, branded Dashboard at 320/390/768/1440 px, Step Preview, typography,
  completion hooks and progress/attempt retention passed.
- With Pro: standalone Pro states were exercised on the same four widths,
  with and without a logo. WordPress 7.1.2/PHP 8.3.35/SQLite and WordPress
  6.0/PHP 8.0.30/MariaDB both passed the navigation browser inventory with the
  packaged candidates. Older Core fallback was exercised with a pre-component
  Core 0.2.3 build and published Core 0.2.1 and 0.2.0 for supported pages.
- Both links reached the configured subdirectory homepage in the same tab.
  Navigation emitted no write requests and preserved the stored Core and
  Workspace rows, including timestamps taken after initial Runner resume.
  Both links retained Pro's existing dirty Workspace warning. The Pro
  validation record documents its own regression commands and package checks.
