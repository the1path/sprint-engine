# SE-002.1 — Linear Sprint Structure Manager

> Historical validation record: results, release stages and remaining checks below
> refer to this ticket at the time it was recorded. Core 0.2.0 is now released.

Validated on 23 September 2026. SE-002.1 only; SE-003 has not been started.

## Implementation and architecture review

The author supplies a complete linear order. The server stores the same explicit
`_se_position`, `_se_next_step_id`, `_se_start_step_id` and `_se_sprint_id` metadata
introduced in SE-002. No data-model replacement, database migration or progress
table change was made. Reviewed against specification sections 1–2, 4, 7, 11,
14–16 and this ticket. The ticket explicitly refines section 11's manual controls;
the v0.1 specification itself has not been rewritten.

- Both CPTs have Sprint/Step create, edit, search, list and publication labels.
- `Content/StructureManager` owns `apply_linear_order()`, `quick_add()` and the
  individual Step metabox's `save_step()` operation. It validates all IDs,
  capabilities, exact active membership and uniqueness before structural writes.
  An order must include every non-trashed associated Step exactly once.
- The service calculates positions 1–N, next links, the terminal unset link and
  the start ID. It verifies writes and the completed chain before committing.
- Quick Add rejects blank/malformed titles, sanitizes text, creates a draft,
  assigns it to the Sprint and appends it to the saved order. The first added
  Step becomes the start. A failed append rolls back the newly created post too.
- `Content/StructureAdmin` provides a thin authenticated `wp_ajax_se_structure`
  adapter, nonce/capability checks, escaped HTML and editor-scoped assets. No
  anonymous AJAX action or member REST endpoint was added.
- WordPress's bundled jQuery UI Sortable supplies dragging. Move up/down buttons
  provide a keyboard-accessible alternative. Proposed positions, start/final
  labels and next links update immediately; Save order persists them separately
  from Gutenberg's content save. Quick Add is disabled while order changes are
  unsaved. Requests disable repeated actions and report success/error locally.
- Structural fingerprints reject stale browser requests, including retries of a
  successful Quick Add after a lost response. Title/stage edits do not invalidate
  the structural fingerprint. Empty orders clear start and launchable.
- The Step metabox retains parent, stage, duration and mode inputs. Calculated
  position/next and Sprint start are read-only. Forged or stale values for those
  fields are excluded from metabox submissions.
- A Step parent change rebuilds both lists, appending at the destination. This
  replaces the old manual-unlink workflow that would otherwise be impossible
  with read-only links. Removing a Sprint's last Step clears its launchable flag.
- Launchable now requires the complete position-ordered chain to match the
  explicit links and start. Existing loop/orphan/foreign/deleted-link warnings
  remain; the manager also warns when stored metadata differs from its list.

## Persistence, assumptions and limitations

- Structure operations own a database transaction. They require transactional
  WordPress `posts` and `postmeta` tables (InnoDB on MySQL/MariaDB), verified using
  table metadata before writes. Unsupported engines fail safely; no core schema
  conversions are attempted. Local tests use the official SQLite integration,
  which supplies compatible transaction semantics and table metadata.
- Manager operations serialize on the affected Sprint rows, locking in sorted
  ID order for moves. Failures roll back and invalidate affected post/meta/query
  caches. Native WordPress hooks can run inside the transaction; arbitrary
  third-party external side effects are not transactional. Do not call this
  service inside an existing transaction.
- Stored structural fields and their native REST registration remain available
  for SE-002 compatibility; PHP/REST callers that deliberately maintain metadata
  directly retain SE-002 validation. Normal UI authors use the manager. Direct
  WordPress metadata APIs remain trusted storage APIs. They do not participate in
  the manager's locking protocol; arbitrary plugin writes and simultaneous manual
  REST restructuring are not covered by its concurrency guarantees.
- Browser requests carry a fingerprint and the complete list. The reusable PHP
  service permits omission of the fingerprint when the caller intentionally
  operates on current server state. Save order can repair stale links using the
  reviewed active list; it is not a general graph/branching validator.
- Membership includes draft, pending, private, scheduled and published Steps.
  Trashed/auto-draft Steps are excluded. A newly created Sprint must first be
  saved as a draft and reloaded. Quick-created Steps default to Content mode.
- Draft publication status and the authoring launchable flag are separate.
  Launchable is not an execution service. Trashing/deleting a linked Step later
  can leave a stale flag or link; the editor warns, and Save order repairs the
  active list. Moving out of an invalid/deleted parent requires restoring that
  parent first; no automatic history or progress mutation is introduced.
- After Step reassignment, save/reload to see calculated values. After a failed
  or uncertain AJAX request, reload before retrying; the controls deliberately
  remain disabled to avoid accidental duplicate actions.
- Administrator-only `manage_options` and per-post edit checks remain. No role,
  PHP/WordPress floor, plugin version or schema version changes were made.
- Lists load all associated Steps; pagination, large-catalog optimization,
  nested stages and a visual flow builder remain out of scope.

## Changed SE-002 assumptions

| Previous authoring workflow | SE-002.1 |
| --- | --- |
| Manually edit position, next and start | Order is the input; all three fields are derived. |
| Add Step opens another editor | Quick Add creates an associated draft inline and supplies Edit links. |
| Unlink incoming/outgoing references before moving a Step | Parent changes through the metabox repair both Sprint lists transactionally. |
| Launchable requires a valid start | Launchable requires a complete valid ordered chain and start. |
| Position ties/zero allowed during manual authoring | A saved manager order normalizes positions to 1–N. Legacy metadata representation remains supported. |
| Individual native metabox writes are not transactional | Multi-post manager operations and parent moves use transactions; ordinary unrelated metabox metadata retains native WordPress behavior. |

SE-002 tests were changed only where controls intentionally changed: nonce,
capability, revision and autosave cases now submit editable estimated minutes;
an invalid mode replaces an editable-next test at the metabox boundary. Rendering
assertions check read-only fields and Quick Add. Existing REST cross-Sprint,
metadata, mode and integer validation tests remain.

The structure suite tests first/five-Step creation, draft/default metadata,
sequential positions, terminal/start links, reordered chains, idempotent saves,
stale fingerprints, omissions, duplicates, foreign/trashed/nonexistent/wrong-type
IDs, malformed inputs, launchable validation, repair, parent moves, read-only UI,
asset scoping and actual AJAX callbacks. Fault injection covers a mid-order write,

state/caches are checked after rollback. Unsupported table engines are rejected
before changes. Anonymous/subscriber callers and invalid AJAX nonces are denied.

fault-injection cases. No test was run against the target host or a production database.

## Local browser verification

Using the in-app browser against the temporary loopback WordPress server:

- Verified Sprint/Step menu and edit-page terminology.
- Opened an empty saved Sprint and quick-created five named drafts from the
  manager. Verified Start/Final, every calculated next link, Edit links and the
  success state; no orphan warnings remained.
- Dragged the second Step to first, saved the order, reloaded, and verified the
  new start and chain persisted. Also exercised a Move Step up button and saved.
- Enabled Launchable using Gutenberg's normal Save draft action and reloaded;
  the flag and AJAX-derived start/order were retained.
- Opened a Step via Edit, saved stage, estimated minutes and Task mode through
  Gutenberg's normal metabox flow, and reloaded to verify persistence. Position
  and next were read-only; the Sprint list reflected the stage and Task mode.
- Inspected the list layout and corrected the action column so its Edit links
  stay within the rows. The temporary browser tab and server were closed.

**Local visual limitation:** Gutenberg's content-canvas blob iframe remained
blank for both Sprint/Step editors and WordPress's ordinary Post editor in the
in-app browser. This prevents claiming visual block-content authoring acceptance
locally. The metabox interactions above worked, and automated tests verify editor
registration and native block-content REST preservation. No WordPress core or
browser workaround was added to the plugin.
