# SE-002 — Content model / authoring validation

> Historical validation record: results, release stages and remaining checks below
> refer to this ticket at the time it was recorded. Core 0.2.0 is now released.

Validated on 23 September 2026. SE-002 only; SE-003 has not been started.

## Implementation and specification review

Reviewed against specification sections 1–2 (content and explicit navigation
links), 4 (Content/Meta responsibility), 5 and 7 (hooks and write boundaries),
11 (native authoring), 14 (foundation preservation), 15 (AT-02 and authoring
portion of AT-03), and 16 (exclusions).

- Existing private, administrator-only CPTs and Gutenberg remain in place.
  `custom-fields` support enables registered native REST metadata.
- `Content/Meta.php` registers typed protected fields, sanitizes values, and
  validates complete candidate states for native metabox and editor REST writes.
- `Content/Authoring.php` provides native metaboxes, same-Sprint selectors,
  ordered associated Step edit links, a prefilled Add Step link, save errors,
  and bounded linear-chain warnings.
- Cross-Sprint links, self-links, wrong/missing object types, malformed fields,
  and launchable-without-start submissions are rejected. Referenced Steps must
  be unlinked before reassignment. Reparenting also validates the outgoing link.
- No database schema, migration, progress service, Runner, member route/API,
  AccessManager, decision mode, integration or automation changes.

## Metadata and assumptions

All keys are single post-meta fields, protected by the `_se_` prefix. REST
exposure is limited to edit context and existing administrator authorization.

| Object | Keys |
| --- | --- |
| Sprint | `_se_estimated_minutes`, `_se_start_step_id`, `_se_launchable` |
| Step | `_se_sprint_id`, `_se_position`, `_se_stage_label`, `_se_estimated_minutes`, `_se_mode`, `_se_next_step_id` |

- Optional integer fields use the native WordPress integer default `0` to mean
  unset; it is not a valid post ID or a measured duration. Blank/null optional
  values clear their rows through the metabox service; REST null uses native
  metadata deletion. Native REST may store an explicit zero with the same unset
  meaning. A terminal Step has no next reference. Set durations must be positive.
- Position is a non-negative integer, defaults to zero, and need not be unique.
  Equal positions use post ID as a stable display tie-breaker. Position does not
  automatically rewrite navigation links.
- A Step can be saved unassigned while being authored, but cannot have a next
  Step without a valid parent Sprint. Draft content can be linked; launchable is
  an authoring flag requiring a valid start, not a publication/execution service.
- Modes are only `content` and `task`; the default is `content`.
- Changing a Sprint selection requires saving and reloading to refresh the
  next-Step options. Instructions appear in the metabox; no JavaScript app is
  required. Create/save the Sprint before using Add Step.
- Obvious loops and unreachable associated Steps are advisory warnings. No
  general graph validator or complete launch-readiness validator is introduced.
- Deleting/trashing content may leave references behind. Editors warn and allow
  repair; no historical progress or structural links are automatically rewritten.
  Content-only REST saves remain possible so Gutenberg's later metabox submission
  can repair a broken link. A launchable flag can become stale after deletion;
  this ticket does not implement execution-time eligibility.
- PHP authoring callers must use `Meta::save()` for relationship validation.
  WordPress's direct metadata APIs are trusted persistence APIs; their sanitizers
  normalize scalar values but do not enforce cross-object invariants. No new
  external/public endpoint bypasses the shared validation boundary.
- Validation failures preserve existing structural metadata. Native metabox
  saves follow the content save, so post title/content can already have saved;
  per-user errors appear on editor reload. A database write failure is reported,
  but multi-field native post-meta writes are not a database transaction.
- The PHP 8.0 / WordPress 6.0 compatibility floor and version/schema constants
  remain unchanged. `.gitattributes` preserves LF PHP files so PHPCS also works
  after Windows checkouts.

Authoring coverage includes:

1. Sprint metadata round trip and native REST typed edit-context exposure.
2. Every Step field round trip, sanitized stage label, Content/Task and unset
   terminal link.
3. Creation of five Steps via native REST, parent assignment, ordered listing,
   explicit linear links, and start/launchable saved in one request.
4. Rejection of cross-Sprint next/start links, self-links, invalid modes, missing

   ambiguous service boolean input.

   and moving a Step referenced as a start or another Step's next link.

   start/launchable together are supported.
7. Actual native save hook, valid/invalid/missing metabox nonces, administrator
   capabilities, protected-meta permissions, anonymous/subscriber REST writes,
   autosave and revision guards.

   trashed start validation and repair, same-Sprint-only next options, and
   associated Step/Add Step links.
9. `use_block_editor_for_post()` for both CPTs and native block content
   preservation through REST creation/updates.
