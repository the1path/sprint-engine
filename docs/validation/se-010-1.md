## Authoring validation and retention

The real-world regression was entering `4-6` into a browser number input. Browser
number coercion could submit an empty value instead of the author's invalid text,
silently clearing the previous estimate. Both duration controls now use text
inputs: Sprint uses `inputmode="decimal"`, Step uses `inputmode="numeric"`.
Associated help explains the supported numbers. No validation JavaScript is added.

Sprint retains exactly one positive decimal value, canonicalized without rounding,
up to nine whole digits and two fractional digits (maximum 999999999.99), and the
Minutes/Hours/Days allowlist. `4-6`, words, zero, negative, overprecision, exponent,
NaN/infinity, HTML and nonscalar values are rejected before any custom field write.
Blank intentionally clears; legacy Sprint minutes are retired so they cannot
reappear. Runner continues to use `Meta::sprint_duration()`.

Step minutes accept positive whole integers within the existing PHP integer
range. Explicit zero, negative, fractional, suffixed text, HTML and nonscalar
values fail. Blank clears. Native REST keeps its integer metadata schema and uses
WordPress's existing `null` deletion convention to clear optional minutes. Internal
zero still means unset; an unrelated Step save does not mistake that stored zero
for an explicitly submitted estimate. Parent changes validate before transactions
or structural writes; existing positions, next links, start and progress survive
rejected fields.

Completion CTA is either two empty fields or a nonempty sanitized label plus a
valid absolute HTTP(S) URL. Partial edits are checked against the stored counterpart.
Incomplete pairs, unsupported/missing schemes, malformed URLs and nonscalar fields
fail before saving any Sprint Engine fields. Valid previous CTA pairs remain
intact. Optional completion text retains plain multiline sanitization; Stage Label
remains unrestricted text. Neither executes shortcodes or embeds.

The shared `Meta::validate()` boundary handles metabox and native REST writes.
Existing duration-unit, Launchable, Step mode, parent and structural checks remain
authoritative. Malformed null text/selection/checkbox replacements are rejected
instead of being silently defaulted. REST invalid metadata returns a safe 400
response. Native calculated structure fields have no new editable controls.

## Author notices

The existing five-minute per-user/per-post transient is reused. Notices say
“Sprint Engine fields were not saved:” followed by an escaped, actionable problem;
they do not echo submitted content or describe all failures as structural.
Malformed metabox payloads also produce feedback. Successful saves clear notices.

Real Gutenberg browser testing exposed two extra visibility issues: its background
metabox POST redirects to an editor GET, and core admin JavaScript relocates ordinary
notices to a hidden block-editor fallback area. The existing notice now survives
the background redirect using a request-context query marker. On the next visible
editor load, Gutenberg shows the notice beside the custom fields with native
`notice notice-error inline` classes and `role="alert"`; Classic Editor retains
the admin notice location. No new form framework, endpoint or notice script.

Invalid custom submissions retain previous Sprint Engine values. This is not a
whole-post rollback: WordPress title/content can already have saved separately
from legacy metaboxes. Open the Meta Boxes panel after reloading to inspect custom
fields and any validation message. Database write failures retain their existing
error handling; this ticket does not claim a new general transaction around Sprint
metadata writes.

## Branding and Trash

RunnerBranding's existing normalization now optionally reports field-specific
Settings API errors at the write boundary. Six-digit hex values normalize to
lowercase without false warnings. Invalid colours and corner styles preserve the
previous safe value; valid sibling changes may save. Empty primary button text
still selects Automatic. Read-side normalization remains safe and silent.

Logo zero intentionally removes the image. Malformed IDs, nonexistent or trashed
attachments, and non-image attachments preserve the previous safe logo and produce
an actionable settings error. Corrupt stored settings still fall back safely.
Live preview, automatic contrast, custom foreground and Reset to Defaults remain.

Structure rows now say Edit · Trash. Adding WordPress's `button-link` class to the
existing `button-link-delete` removes the button box; native red text, hover/focus
and keyboard button semantics apply. No custom icon or CSS was needed. Internal
`remove`, confirmation, dirty-order guard, permissions, transaction, structure
repair and unassigned restoration remain unchanged. The AJAX audit found existing
errors for blank Quick Add, invalid Sprint/Step/order, stale revision and permission
failures; no endpoint redesign was necessary.
