# SE-001 acceptance review

> Historical validation record: results, release stages and remaining checks below
> refer to this ticket at the time it was recorded. Core 0.2.0 is now released.

Only Plugin Foundation is implemented. SE-002 has not been started.

| Criterion | Implementation / verification |
| --- | --- |
| Installable standalone plugin | Bootstrap/header, namespaced runtime classes, runtime-only ZIP builder; no runtime dependencies. |
| AT-01 clean activation / tables | Real WordPress integration checks with PHP warnings/notices treated as failures. Both prefixed progress tables accept rows. |
| AT-02 admin CPTs | Both types expose admin UI and native block-editor support; administrators can create content. |
| Two specified progress tables | Required fields, nullable timestamps, unsigned IDs, individual lookup indexes, unique composite keys, no foreign keys. |
| Versioned, repeatable installation | Separate options, `dbDelta()` application and verification, no changes on repeat, upgrade and failure/recovery tests. |
| AT-18 retention | Exact row comparisons before/after deactivation/reactivation; content retained; uninstall retains data. |
| Privacy | Native REST reads denied to anonymous users/subscribers and allowed for administrators. No member REST routes. |
| Scope | No Step metadata/relationships, Runner, branching, commerce, automation, or later services. |

## Executed checks

- PHP 8.3.35 syntax checks for all project PHP files.
- WordPress coding standards via the locked Composer development dependencies.
- Integration suite on isolated WordPress 7.1.2 with the official SQLite Database
  Integration plugin and a `se_test_` table prefix. The suite uses actual WordPress
  activation, REST, post, database, and `dbDelta()` APIs.
- Runtime ZIP contents reviewed to exclude development tooling and dependencies.
- Git whitespace/diff review.

## Remaining target-site checks

- MySQL/MariaDB integration run: the local test environment uses SQLite, so
  native MySQL/MariaDB behavior remains unverified.
- Browser upload/activation, visual admin menus, and Gutenberg editing on the
  target site; programmatic registration/content creation were checked locally.
- Confirm PHP 8.0 / WordPress 6.0 compatibility baseline against hosting. Those
  exact minimum versions have not been exercised locally.

Tests intentionally inject database failure and a newer schema version. Generic
failure log entries in those cases are expected; activation itself must be silent.
