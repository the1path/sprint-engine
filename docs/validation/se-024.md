# SE-024 — Sprint Engine Typography

Open **Sprints → Settings → Runner Branding → Typography**. The **Font**
selector offers **Use website font**, **System default**, and a **Choose a font**
group with Poppins, Inter, Roboto, Open Sans and Lato. Changes affect the live
preview immediately and the Runner, My Sprints and administrator Step Preview
after saving. Gutenberg font selections and authored inline typography retain
their own font family.

## Settings and upgrade

`sprint_engine_runner_branding` has one additional allowlisted key, `font`.
Accepted values are `website`, `system`, `poppins`, `inter`, `roboto`, `open-sans`
and `lato`. Invalid submissions retain the last valid selection and report a
Settings API error. Corrupt stored values, a missing key and a missing option
all resolve to `website`. Existing colour, logo and corner values are read
through the same normalization as before. Reset deletes the option and restores
website mode. Selecting **System default** explicitly retains the pre-SE-024
Runner and Dashboard stack.

The deliberate upgrade default is website mode even if an administrator already
saved other branding fields. The visual change occurs on the next application
request when the site has a supported body font. Schema and release metadata
require no change.

## Website font resolution

- Read the root `typography.fontFamily` from `wp_get_global_styles()`. A
  registered family on its own does not establish a body selection. Resolve the
  WordPress preset reference in either native syntax using
  `wp_get_global_settings()`, with custom, theme and core precedence.
- Use the leading declared family when it has a matching registered face with
  a usable same-origin source. Supported sources are theme `file:./` paths
  that exist and same-origin HTTP(S) URLs for WOFF2, WOFF, TTF or OTF, including
  same-origin Font Library URLs. The loader uses normal, italic and oblique
  faces with static or variable weights and a scoped family alias. The
  browser falls back to the system stack if the source fails or lacks a glyph.
- For a leading CSS generic or recognized system family, preserve the known
  generic/system entries in order and append the Sprint Engine system fallback.
  Unsupported family names, unresolved CSS variables and unavailable or
  third-party-only faces fall back to the system stack.
- Classic or hybrid themes can participate by declaring a supported global body
  font. Typography defined only in theme CSS, Customizer controls or a
  page-builder kit is outside the Global Styles lookup. CSS-only fonts, custom
  CSS variables, CDN-hosted faces and specialized descriptors such as
  `font-stretch` and `unicode-range` are outside this resolver. WordPress and
  other extensions continue to manage assets for their own blocks and pages.

[WordPress Global Styles API](https://developer.wordpress.org/reference/functions/wp_get_global_styles/) ·
[WordPress typography settings and registered faces](https://developer.wordpress.org/themes/global-settings-and-styles/settings/typography/)

## Bundled fonts and privacy

The package contains 14 Latin-subset WOFF2 files and the five original SIL Open
Font License 1.1 notices under `assets/fonts/` (approximately 433 KiB in
total). Poppins and Lato include regular and bold weights, each with italics.
Inter, Roboto and Open Sans include normal and italic variable-weight faces.
The system stack covers glyphs outside the bundled subsets. The files are from
Fontsource 5.3.0, using the packages below.

- [Poppins](https://www.npmjs.com/package/@fontsource/poppins/v/5.3.0)
- [Inter](https://www.npmjs.com/package/@fontsource-variable/inter/v/5.3.0)
- [Roboto](https://www.npmjs.com/package/@fontsource-variable/roboto/v/5.3.0)
- [Open Sans](https://www.npmjs.com/package/@fontsource-variable/open-sans/v/5.3.0)
- [Lato](https://www.npmjs.com/package/@fontsource/lato/v/5.3.0)

Sprint Engine makes no server-side requests to detect fonts. It registers
bundled faces only for a manual selection or for live selection on the settings
page. The preview browser requests a face when it is used. No mode calls the
Google Fonts service. WordPress's normal theme and block assets can independently
request fonts for authored content or third-party UI.

## Pro compatibility

Source review of the local Sprint Engine Pro checkout at `dc48cff`.

| Pro surface | Behaviour with this Core change |
| --- | --- |
| Workspace fields and controls in the Runner, completion recommendations and access CTA, My Sprints navigation and History/Journey card actions | Inherit the Core container's family through CSS inheritance or `font: inherit`. |
| Standalone Sprint History (including detail and print), My Journeys and Journey Hub | These applications emit Core branding variables and specify their own system stack in `history.css`, `my-journeys.css` and `journey.css`. Each requires a Pro CSS and font-loader update for parity. |
| Pro administrator member-preview notice inside Core screens | `member-preview.css` sets its own system font. Adopting the selected family there requires a Pro CSS change. |
| Public Directory shortcode | Emits the Core variables but uses `font: inherit` inside the host theme page. Applying the Core selection to this component would require a separate Pro decision and scoped styles. |

`RunnerBranding::css()` continues to return validated declarations. It now
includes `--se-font-family`. Standalone consumers can set
`font-family: var(--se-font-family, system-ui)` on their root, keep descendant
controls inheriting the family, and call
`RunnerBranding::enqueue_fonts( $handle )` after enqueueing the consumer's
stylesheet. Guard the method with `is_callable()` when supporting older Core
versions. The method attaches the saved selection's font-face rules to the
provided WordPress handle. Embedded components within the existing Core roots
already receive the loaded faces. The source review establishes inheritance
paths and overrides. Full Pro typography parity is unverified.

## Verification

Disposable WordPress 7.1.2 with PHP 8.3.35 and the SQLite Database Integration,
and WordPress 6.0 with PHP 8.0.30 and MariaDB 10.11.11. Both used non-default
database prefixes and loopback HTTP. Chrome/Playwright checked typography and
tested layout at 1440, 768 and 390 px.

- Computed font stacks and rendered font faces on Runner Welcome, Step and
  Completion, My Sprints, administrator Step Preview and live branding preview.
  The browser rendered all five bundled selections, Manrope on Twenty
  Twenty-Five, and Source Serif on Twenty Twenty-Two after a saved Global Styles
  selection. Twenty Twenty-One, with no detectable Global Styles body font,
  used the system stack.
- Live changes, Settings API save/reload/reset, an existing option without
  typography, corrupt values, rejected tampering and denied member or
  missing-nonce saves. Blocking font requests confirmed the rendered system
  fallback for both a bundled and a website font. Request logs recorded no
  Google Fonts or third-party font requests in the Core fixtures.
- Headings, labels, controls and plain Step text followed the selection.
  Gutenberg preset heading fonts and a block button's authored font remained
  effective. Controls fit at each viewport. Admin typography outside the preview
  and ordinary site routes stayed outside the plugin's styles.
- The typography fixture compared attempt identity, progress rows, versions
  and rewrites before and after. Opening the active Runner continued to refresh
  its two existing resume timestamps. The original branding suite also
  compared exact content and progress snapshots after save and reset.
- On Elementor 4.4.0 with Twenty Twenty-One, an Elementor kit rendered Georgia
  on its own page. Core's website selection fell back to system, and a saved
  Poppins selection applied to the Runner and Dashboard while the Elementor
  page kept Georgia. Core's live font change added no Google Fonts requests.
  Elementor One separately enqueued its Roboto Google Fonts stylesheet in
  WordPress admin, including on the branding page, with Elementor's frontend
  Google Fonts setting disabled. Elementor Pro and other builders were outside
  this check.

PHP lint passed for 67 files and Composer PHPCS passed. The 19 Composer test
scripts passed individually with fresh disposable databases as required
(1,791 assertions, including the Runner, REST and Dashboard HTTP checks).
The optional Core/Pro Workspace recovery suite passed nine assertions.
All 39 JavaScript tests passed, as did the 45 release metadata checks and exact
67-file package verification. The package check included WOFF2 signatures and
the bundled licence notices. Existing Chrome/Playwright suites passed for
Runner, Dashboard (read, lifecycle, branding and extension modes), branding,
and administrator Step Preview. The Step Preview regression also passed on
the minimum-runtime installation.

To reproduce the dedicated browser checks, use a disposable install with
Twenty Twenty-Five or Twenty Twenty-Two and Twenty Twenty-One. Set
`SE_TEST_WP_ROOT`, `SE_TEST_DISPOSABLE=yes`, and `SE_TEST_HTTP_BASE` for the
running loopback site.

```sh
php tests/browser/typography-fixture.php > fixture.json
node tests/browser/typography.cjs fixture.json
php tests/browser/typography-fixture.php verify fixture.json
php tests/browser/typography-fixture.php classic
node tests/browser/typography.cjs fixture.json classic
```

The browser suite saves Poppins screenshots of each surface at all three
widths under `SE_BROWSER_OUTPUT` (default `.tools/se024-browser`). The local
evidence for this run is under `.tools/se024/screenshots/` and
`.tools/se024/screenshots-legacy/`. Real-device and non-Chromium rendering
were outside this verification.
