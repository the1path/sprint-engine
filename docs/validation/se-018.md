## Exact contract and compatibility

```php
do_action( 'sprint_engine/runner_completed_followup_actions', $completed );
```

The action receives exactly one array with exactly three integer fields:

| Field | Source |
| --- | --- |
| `sprint_id` | Core route-resolved, authorized Runner Sprint ID |
| `attempt_id` | Current authenticated member's canonical completed attempt ID |
| `attempt_number` | That canonical attempt's number |

Core constructs the payload once from the existing server-authorized Runner
context, and passes it to both completion actions. Request/query identifiers
cannot select the user, Sprint or attempt. No history lookup or extra service
operation is introduced.

The new action fires once on every authenticated, authorized completed Runner
render, immediately after the completion **Back to My Sprints** link, before
the closing `se-runner__completion` container. Order is creator completion
message/CTA → existing `runner_completed_actions` → Restart Sprint and its
status/noscript content → Back to My Sprints → new follow-up action.

Anonymous, not-started, in-progress, denied, missing, malformed and unavailable
route contexts do not fire either completion action. A historical completed
attempt cannot trigger them while the canonical attempt is in progress.
Revisiting completion fires both again; these are presentation hooks, not
once-only lifecycle events. Return values are ignored.

The SE-017 `runner_completed_actions` keeps its name, single array argument,
conditions and original position before the Core controls. SE-017 Dashboard,
denial and anonymous gateway contracts are unchanged. No listener produces no
additional visible markup. The creator CTA, Restart Sprint, Dashboard links,
progress and focus order remain intact. Template overrides own hook placement.
Historical validation records were not rewritten.

Callbacks are trusted installed PHP: escape output by context, independently
authorize linked destinations, and preserve privacy/access rules. Core neither
sandboxes callbacks nor guarantees that arbitrary extension code is read-only.
The current member is available through `get_current_user_id()`; no member ID or
other member's context is added to the payload.
