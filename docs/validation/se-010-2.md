# SE-010.2 — Immediate & Field-Level Validation Feedback

> Historical validation record: results, release stages and remaining checks below
> refer to this ticket at the time it was recorded. Core 0.2.0 is now released.

## Scope and cause

SE-010.1 correctly rejected invalid metadata and retained previous values. Gutenberg
saves legacy metaboxes separately from post content, so its content save could report
success while the metabox error waited for the next visible editor load. This change
adds immediate feedback to that existing authoring surface. Server validation,
Runner behaviour, schema/version, structure transactions, access and progress remain
unchanged. No endpoint, migration, CSS dependency or form framework was added.

## Editor behaviour

`assets/js/authoring-validation.js` loads only on Sprint and Step edit screens,
using `Assets::version()`. All messages come from translated PHP strings. On input,
change and blur it checks duration, minutes and the CTA pair. Errors are plain text
immediately beneath the relevant field; both CTA controls share one message. Other
constrained controls only need server fallback, without speculative client rules.
Repeated identical error text is not rewritten, and feedback does not move focus
while typing.

The script calls the public `core/editor` actions `lockPostSaving` and
`unlockPostSaving` with the name `sprint-engine-authoring-validation`. It uses the
same stable ID for one non-dismissible `core/notices` error. Correcting one field
does not unlock while another is invalid. Correcting all fields removes only this
notice and lock. It does not intercept core buttons, poll the DOM, change editor
internals or lock autosaving. WordPress itself disables its manual save controls.

The API was checked against the [WordPress editor reference](https://developer.wordpress.org/block-editor/reference-guides/data/data-core-editor/)
and the [WordPress 6.0 source](https://github.com/WordPress/WordPress/blob/6.0/wp-includes/js/dist/editor.js),
which includes these actions at the plugin's documented minimum version. Runtime
browser verification used the existing disposable WordPress 7.1.2 installation;
this is not a claim of running the complete suite on WordPress 6.0.

Classic Editor runs the same field checks and a native form submit guard. An
invalid submit is prevented and focuses the first invalid field. Valid submissions
retain normal WordPress behaviour. JavaScript never defines the write boundary.

## Field identity, accessibility and fallback

`Meta` errors retain HTTP `status: 400` and add a `fields` array. Individual scalar
errors name their metadata key; a CTA pair error names both keys. Structural errors
that cannot sensibly identify an editable control remain general notices. The
validator still returns its first server error; client checks can display several
independent invalid fields together.

The existing per-user/per-post transient now stores `message` and `fields`, without
raw input. Older string transients still render as general errors. Visible rendering
consumes the transient while retaining the data on the Authoring instance for inline
markup, including Classic Editor's earlier admin notice. Hidden `meta-box-loader`
requests and redirected `se-metabox-response` requests still do not consume it.

Server fallback errors appear next to duration value/unit, CTA, parent Sprint,
minutes, mode, stage, Launchable and completion message where applicable. Native
controls have `aria-invalid="true"` and their unique error ID in `aria-describedby`.
Existing duration/minutes/stage help IDs are preserved. Messages use readable bold
text and polite live regions; colour is not required. Client correction removes the
invalid state and error relationship while retaining help. A fallback remains visible
until the author interacts with that control; fields show the safely retained saved
values, not rejected input. A successful valid server save deletes stale feedback.

## Rule consistency and limits

Duration accepts blank or positive decimal text with at most nine whole digits and
two fractional digits. Minutes accept blank or positive whole integers up to the
server's `PHP_INT_MAX`, supplied as a decimal string so JavaScript does not round
large integers; PHP's rejection of leading-zero integers is retained. CTA requires
both blank or meaningful label text plus an absolute HTTP(S) URL.

JavaScript checks raw URL scheme, whitespace/HTML/backslashes, ASCII text, host
labels and browser URL parsing. PHP's `FILTER_VALIDATE_URL`, `esc_url_raw` and text
sanitization remain authoritative. Browser URL parsing and PHP filtering are not
identical for unusual credentials/URL syntax or crafted HTML labels; such bypasses
and residual server failures retain saved values and use the inline reload fallback.
No broad URL-validation framework or server request on each keystroke was added.
