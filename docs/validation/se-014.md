## Authoring behaviour

Previously, an auto-draft showed only “Save this Sprint as a draft, then reload
to add and order Steps.” It hid the manager's purpose and required a manual
refresh after Gutenberg's first save.

`StructureAdmin::render()` now displays a `Sprint Structure` heading, muted
dashed container, explanatory text and a natively disabled Add Step button.
Primary copy is “Save this Sprint to start adding Steps.” Supporting copy explains
that saving enables creating, ordering and managing Steps. The placeholder has
no active sortable or mutation selector, creates no fake records and triggers
no save. Administrator and per-post edit checks protect both states.

Gutenberg's first successful explicit save activates the existing manager without
page refresh. The script feature-detects the documented
[WordPress editor selectors](https://developer.wordpress.org/block-editor/reference-guides/data/data-core-editor/)
through `wp.data`: `isSavingPost`, `isAutosavingPost`,
`didPostSaveRequestSucceed`, `getCurrentPostId` and `getCurrentPostAttribute`.
It observes a non-autosave saving state followed by successful completion,
requires the same post ID and a saved status, then requests one `refresh`
operation. It replaces only the placeholder and initializes the existing
sortable/actions. It unsubscribes after success. Failed refreshes retain the
disabled placeholder with a safe retry/reload message; a later explicit save
can retry. There is no editor dispatch, forced save, hidden autosave, interval,
server polling or page reload. Classic Editor keeps its native save/navigation;
it needs no SPA listener or editor dependencies.

The existing authenticated `wp_ajax_sprint_engine_structure` action handles the
read-only refresh. It requires the Sprint nonce, `manage_options`, `edit_post`
and a valid saved Sprint, rejecting auto-drafts, missing/wrong-type objects and
unauthorized callers. It ignores mutation payloads, performs no writes and
returns only the existing escaped manager fragment. No anonymous handler or
public status endpoint was added.

Every active row now renders `.se-step-status[data-status]` from the actual
`WP_Post::post_status`, using the registered WordPress status label and escaped
output. Labels include Published, Draft, Pending Review, Private and Scheduled.
Non-published badges use readable amber text/border/background; Published is
neutral. Text carries the meaning independently of colour. Title, stage, mode,
Start/Final, next link and actions retain the existing layout and responsive grid.
Quick Add remains Draft and its fresh AJAX fragment immediately shows its badge.

One translated aggregate warning counts all non-published active Steps, with
singular/plural `_n()` copy explaining that they must be published before launch.
Zero/all-Published lists have no warning. The existing setup checklist adds a
distinct `Publish all Sprint Steps` item before Launchable. It remains advisory
saved-state guidance refreshed by the existing editor reload workflow; only the
Structure placeholder receives live first-save replacement.

## Publication correctness and retention

`Meta::publication_readiness()` reads the same active membership as `Meta::steps()`
and returns total/unpublished counts plus readiness. Ready means at least one
active associated Step and every one has exactly `post_status === 'publish'`.
Draft, Pending, Private and Future remain authoring-visible; Trash/auto-draft
membership exclusions are unchanged. Structural correctness stays exclusively
in `StructureManager::is_linear()`; that class and structural revision design
are unchanged.

Shared metadata validation rejects a true Launchable candidate with unpublished
Steps using “Publish every Sprint Step before making this Sprint Launchable.”
The existing HTTP 400/field-error boundary identifies the Launchable field. Native
REST rejects before content or metadata persistence; the metabox service validates
the whole candidate before writing. Already saved true metadata is retained when
a Step later becomes unpublished; an invalid checked candidate is rejected with
feedback, rather than silently clearing Launchable or publishing Steps.

`Availability::reason()` independently checks publication readiness and reports
“Runner unavailable — one or more Sprint Steps are not published.” Its existing
callers naturally protect Runner, Dashboard eligibility and REST Start, Restart
and Complete. Member responses remain generic and contain no unpublished title,
content or administrator reason. Republishing restores normal eligibility.

Status changes preserve parent, position, next/start links and structural revision.
Tests compare exact enrolment and Step-progress rows during blocked operations and
after restoration. No attempt reset, progress deletion, database field, option,
custom status or migration was added. Plugin **0.2.0**, schema **2**, PHP **8.0**
and WordPress **6.0** floors are unchanged. Existing ordering, stale revisions,
transactions/rollback, parent moves, Trash, explicit links and security assertions
are retained. Happy-path fixtures now explicitly publish their Steps; the Trash
rollback assertion verifies restoration to their actual Published state.
