# SE-004.1 — Runner URL Admin UX

> Historical validation record: results, release stages and remaining checks below
> refer to this ticket at the time it was recorded. Core 0.2.0 is now released.

Testing on the target host found that the working Runner route was difficult to
find because the intentionally private Sprint post type has no normal View or
permalink controls. This refinement exposes the existing route in admin.

## Implementation and files

Created `src/Content/RunnerAdmin.php`, `src/Runner/Availability.php`,
`assets/js/runner-admin.js`, `tests/integration/runner-admin.php`, and this file.
Changed `src/Plugin.php` to register admin hooks, `src/Runner/Runner.php` to call
the extracted readiness helper, `composer.json` to include the sixth suite,
`README.md`, and only the Sprint admin wording in the specification.

Admin hooks: `add_meta_boxes_se_sprint`, `post_row_actions`,
`manage_se_sprint_posts_columns`, `manage_se_sprint_posts_custom_column`,
`quick_edit_custom_box`, `admin_init`, and `admin_enqueue_scripts`.

The block-editor-compatible Runner URL panel replaces the legacy hidden slug
box. It reads `WP_Post::post_name` directly and submits a native `post_name`
input. URLs exclusively use `Runner\Routes::url()` (including home/subdirectory
and trailing-slash semantics). Auto-drafts and empty slugs get save-first guidance.
Saved unavailable Sprints still show their canonical URL and an admin-only reason.

Availability extracts the existing Runner content checks: published, no Sprint
password, Launchable, valid linear structure. Row actions and the Runner column
show active links only for ready Sprints with a slug and an editor capability.
These checks do not grant member access or inspect/modify anyone's progress.
Login, AccessManager and per-member runtime state still control actual admission.
No Step row action is added. Native list columns/sorting/filtering remain intact.

Quick Edit adds one `post_name` input through the Runner custom column hook.
WordPress's existing hidden `post_name` row data and `inline-edit-post` script
populate it and submit the normal `inline-save` request. No custom Quick Edit
JavaScript, endpoint, or structure input is needed.

## Saving and security

Normal `post.php`/Gutenberg metabox saving handles the `update-post_ID` nonce and
edit capability; native editor REST uses its existing authentication/schema.
Core Quick Edit checks `inlineeditnonce` and `edit_post`. Native `edit_post()` /
`wp_update_post()` sanitisation and uniqueness own persistence. There is no custom
save_post handler or new metadata. Existing administrator-only CPT capabilities
remain unchanged. The admin_init guard discards non-string Sprint form slugs
before core string handling; this guard performs no write or authorisation.
REST malformed input is governed by the existing native schema.

Core autosave/revision handling remains responsible for canonical content; the
integration test verifies an autosave revision cannot replace the parent slug.
Output uses context-appropriate escaping. No arbitrary URL/path field is accepted.
Title, Step slugs, structure and enrolment/progress data are untouched by slug edits.

The generic `/sprint/{slug}/` rule is unchanged, so changing a slug needs **no
rewrite flush**. The new slug resolves the same Sprint ID. The old slug has no
custom redirect or history feature. Public/publicly_queryable remain false and
normal CPT rewrite remains disabled. No schema, member REST or progress changes.

## JavaScript and refresh behaviour

The small Sprint-editor-only script uses Clipboard API and an aria-live status.
If clipboard access fails or is absent, it selects/focuses the readonly URL field
and asks the user to copy manually. No new library is added. In Gutenberg it also
synchronises slug field changes to core/editor so normal REST and metabox saves
agree. Classic editor uses the same native field without the editor data dependency.
The panel deliberately shows saved values: save and reload after changing slug,
publication or Launchable to refresh its URL/status. Quick Edit refreshes the row
through WordPress's existing AJAX response.

## Limitations and target host checks remaining

No known failing local checks. The panel requires save/reload for refreshed saved
values. Availability describes content readiness, not a guarantee that every
member's access policy or historical progress state succeeds. Clipboard fallback
is provided; browser clipboard permission behaviour varies. The existing pretty
permalink requirement remains. No new platform or role assumptions were added.
Minimum WordPress/PHP versions and MySQL/MariaDB were not separately tested here.

After deploying only the plugin directory/package, manually verify on the target host:

1. Edit an existing Sprint; check visible native slug/canonical URL, Copy URL and
   View Runner with the site's actual URL, HTTPS and permalink configuration.
2. Change slug, save/reload, and open the new Runner URL without flushing rewrites.
3. Check All Sprints hover action and Runner column, then Quick Edit population,
   sanitisation and saving. Verify the resulting link and unchanged title.
4. Check Draft, non-launchable, invalid and password-protected Sprints do not
   present a misleading active View Runner action.
5. Confirm Structure Manager operations, existing Runner login/resume/content,
   and unrelated admin screens still work with the host's plugins/theme/cache.
6. Run destructive integration suites only on a separate disposable installation,
   never against the development site's existing authored content or progress.

SE-005 and merging to main are outside this change.
