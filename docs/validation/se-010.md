## Sprint duration

Protected Sprint metadata registered by `Content\Meta`, in administrator-only
native REST edit context:

| Key | Type / accepted values |
| --- | --- |
| `_se_estimated_duration_value` | Decimal string, blank or positive, up to nine whole digits and two decimal places |
| `_se_estimated_duration_unit` | String enum: `minutes`, `hours`, `days`; default `minutes` |

`Meta::duration_value()` validates without rounding. Negative/zero, exponent,
NaN/infinite-style, malformed, HTML/CSS, array/object and overprecision input is
rejected at the shared metabox/native REST boundary before writes. The upper
bound is 999999999.99. Normalization removes leading/trailing zeros: 4.00 → 4,
1.50 → 1.5. This is display metadata; a day is not converted to active-work hours.

`Meta::sprint_duration()` returns `value`, `unit`, translated/localized `label`,
or an empty array. Both new keys must exist and form a valid nonempty duration;
otherwise valid legacy Sprint `_se_estimated_minutes` displays as minutes.
Legacy 240 remains “240 minutes”, never implicitly “4 hours”. Intentional saves
of the new value through the metabox retire the Sprint legacy key; native REST
does so after successful insertion/update. Explicit blank saves therefore cannot
revive the old minutes. Other metadata saves retain the legacy fallback.

Start context consumes the helper and shows “Estimated time: 4 hours”, with
singular/plural labels. Step context does not contain Sprint duration. Step
`_se_estimated_minutes`, its integer validation, input and “About 10 minutes”
presentation are unchanged. No duration edit touches member progress.

## Remove workflow and correctness

Each editable/deletable Structure row has Remove. Native confirmation names the
Step and explains Trash, rebuilding and unassigned restoration. Cancel makes no
request. Dirty reorder state disables Remove and Quick Add, with Save order
guidance; a handler guard also blocks dirty Remove. Successful replacement uses
the existing fragment mechanism, announces “Step moved to Trash. Structure saved.”
and focuses New Step title. Uncertain failures retain the existing reload policy.

The existing authenticated `wp_ajax_se_structure` supports operation `remove`.
Its payload contains only action, Sprint ID, Step ID, revision, operation and
existing nonce. `StructureManager::trash_step()` validates strict IDs, membership,
current revision, manage_options, Sprint edit and Step edit/delete permissions.
All active associated Steps must be editable under the existing validation model.
Malformed, foreign, stale and already-trashed targets are rejected before writes.

Within the existing Sprint-row-locked transaction, the service deletes the
removed Step's `_se_sprint_id`, `_se_position`, `_se_next_step_id`, verifies their
absence, and rebuilds remaining positions, explicit next links and Sprint start.
An empty result clears start and Launchable. It calls core `wp_trash_post()`,
verifies Trash status and rechecks membership/structure before commit. WordPress
Trash must be enabled: `EMPTY_TRASH_DAYS=0` is rejected rather than allowing core
to permanently delete. No progress mutation is added to this authoring operation.

Restoring with WordPress Trash retains title, Gutenberg content, stage, minutes,
mode and Featured Image, but leaves the Step unassigned. An author can assign it
explicitly through the existing Step editor. The existing ProgressService remains
responsible for stale current-pointer recovery and preserves historical rows.

Atomicity retains the existing transactional-content-table requirement (InnoDB on
MySQL/MariaDB). Faults in metadata repair, core trash veto and commit roll back
structure, post status and metadata, with post/meta/query caches invalidated.
Core trash/status hooks execute inside the transaction. External hook side effects
(email, network, files, nontransactional storage or a hook committing independently)
cannot be rolled back; core comments or third-party tables are not newly included
in the existing storage-engine gate. This ticket does not redesign that boundary.

## Featured Images

Both private CPTs support native `thumbnail`. At init, `Authoring` preserves
unrestricted theme thumbnail support or extends restricted/absent support only
with `se_sprint` and `se_step`. Ordinary Posts/Pages retain their theme's choices.
There is no custom uploader, duplicate control or extra tutorial metabox.

After existing access/current-Step checks, Runner resolves only the current
state's image: Sprint on Start and Completion, current Step while in progress.
Missing Step images never fall back to Sprint. Invalid/deleted/non-image/trashed
attachments return empty markup. Core `wp_get_attachment_image(..., 'large')`
generates the image, retaining native attachment alt and responsive attributes.
Login/error contexts expose no image information.

The image is first in `.se-runner__main`, after title/progress and before primary
content. There is no wrapper or reserved gap when absent. Scoped CSS fills the
content width, uses object-fit cover, a 16:7 aspect ratio (16:10 at <=480px), and
the existing `--se-radius`. Body Gutenberg images keep their existing styling.
