# SE-008 — Runner Branding & Appearance Settings

> Historical validation record: results, release stages and remaining checks below
> refer to this ticket at the time it was recorded. Core 0.2.0 is now released.

## Scope and architecture

Site-wide presentation settings for every Sprint, with no per-Sprint overrides.
The completed SE-001–SE-007 architecture, routes, REST contracts, progress services,
schema, events and cache policy remain unchanged. No migration or version bump.
No specification change was required; this is the explicitly requested post-v0.1
productisation enhancement. No new public filter was necessary.

`Settings\RunnerBranding` owns defaults, read/write normalization, contrast,
derived shades, CSS declarations and WordPress logo markup. `Settings\SettingsPage`
owns the admin UI. Plugin bootstrap registers its hooks:

- `admin_menu`: Settings beneath `edit.php?post_type=se_sprint`, slug `se-settings`.
- `admin_init`: Settings API group `se_branding`, one array option.
- `admin_enqueue_scripts`: assets restricted to the returned submenu hook and
  `manage_options` users.
- `admin_post_se_reset_branding`: capability/nonce-protected reset.

Save uses core `options.php`, `settings_fields`, `manage_options`, Settings API
sanitization and native success/warning notices. Reset uses its own POST form,
`check_admin_referer('se_reset_branding')`, and **deletes only the branding option**.
It redirects to the settings page with the native success notice. No rewrite flush,
content reconstruction, progress mutation or reactivation is needed.

## Option schema and validation

Single option: `sprint_engine_runner_branding`.

| Key | Default | Accepted value |
| --- | --- | --- |
| `logo_id` | `0` | Integer or digit-string ID of an existing image attachment; zero removes |
| `primary` | `#205b48` | Six-digit hexadecimal colour |
| `background` | `#f3f6f5` | Six-digit hexadecimal colour |
| `surface` | `#ffffff` | Six-digit hexadecimal colour |
| `text` | `#203630` | Six-digit hexadecimal colour |
| `muted` | `#50645d` | Six-digit hexadecimal colour |
| `corner_style` | `soft` | `square`, `subtle`, `soft`, `rounded` |

`get()` returns a complete validated configuration with no required option row.
One normalization method allowlists the keys on both read and write. Colours
must match six hex digits and pass `sanitize_hex_color`; saved values become
lowercase. Short hex, arrays, arbitrary CSS/HTML and unknown keys cannot reach
CSS output. Invalid/missing colours and corners retain valid saved values on
write; corrupt/partial storage falls back to central defaults on read. Invalid,
missing, non-image, negative, fractional or boolean logo IDs become zero.

Media uses core `wp.media` restricted to images. Choose and Remove update both
the thumbnail and illustrative logo immediately. Only the attachment ID persists.
Frontend markup uses `wp_get_attachment_image('medium')`, attachment alt text
with site-name fallback, and maximum 180px width/64px height with responsive
containment. Deleted/non-image attachments render nothing. No remote URL field,
custom uploader, SVG sanitizer or separate mobile logo is introduced.

## Appearance and accessibility

`runner.css` defines safe defaults and consumes `--se-primary`, `--se-background`,
`--se-surface`, `--se-text`, `--se-muted`, `--se-on-primary`, `--se-radius`, and
`--se-control-radius`. Derived properties are `--se-hover`, `--se-accent`,
`--se-link`, `--se-label`, `--se-secondary-text`, `--se-secondary`,
`--se-secondary-hover`, `--se-border`, `--se-control-border`, `--se-track`,
`--se-task`, `--se-quote` and `--se-notice-border`.

Runner's existing scoped enqueue adds validated declarations through
`wp_add_inline_style('se-runner', ...)` under `body.se-runner`. No untracked style
block or repeated per-element inline colours. Unrelated frontend pages receive
neither Runner assets nor branding CSS. Settings changes affect the next request;
no generated CSS files or cache invalidation is needed. SE-007 `Assets::version()`
continues on Runner assets and also fingerprints both new admin assets.

Built-in primary/surface preserve the exact legacy secondary shades, including
progress `#276a55`, primary hover `#164333` and track `#dce6e0`. Custom colours use
deterministic sRGB channel blends generated as ordinary hex, avoiding any
`color-mix()` browser dependency. Light-brand secondary buttons use automatically
contrasted text; custom links/labels blend the primary toward a contrasting
surface foreground. These are internal derived values, not additional settings.

Primary foreground compares black/white WCAG contrast ratios using linearized
sRGB relative luminance (0.2126 R + 0.7152 G + 0.0722 B). The greater ratio wins,
without changing the chosen primary colour. Custom hover darkens white-text
primaries and lightens black-text primaries to preserve readable foregrounds.
Original focus outlines remain, reinforced by white/black rings so a chosen
brand surface cannot hide keyboard focus. Busy status remains separately styled.

Corner mapping: square = 0, subtle = 0.5rem, soft = 1rem, rounded = 1.5rem.
The default soft style retains the legacy 0.5rem control/notice radius alongside
the 1rem main card/progress radius. Other choices use their mapped radius for both.

The lightweight preview reuses Runner CSS classes and the same custom-property
model, with no iframe or progress endpoint. Vanilla JS plus the core colour picker
updates colours, corner style and media selection immediately. The preview's
buttons are inert `type=button` controls outside the save form. JavaScript colour
math is checked against PHP-generated values in the browser suite.

A non-blocking live warning checks main/muted text against surface/background at
4.5:1. This is **not a full accessibility checker**: arbitrary administrator
combinations, authored block colours, gradients/images or other plugin/theme CSS
can still produce poor contrast. Saving remains allowed. Real keyboard, zoom,
screen-reader and host-theme verification remain required.
