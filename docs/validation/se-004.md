## Route and request lifecycle

`Routes::RULE` is `^sprint/([^/]+)/?$`, registered at the top on `init` and mapped
to `index.php?se_sprint_slug=$matches[1]`. `se_sprint_slug` is a dedicated public
query variable. Both slash variants work. `Routes::slug()` requires the actual
matched rewrite and captures the path, so query-string flags on unrelated URLs
cannot invoke Runner or override its Sprint. The request filter removes supplied
feed/preview/post selectors and keeps unrelated posts out of the main query.
Steps remain non-public with no rewrite or member permalink.

`Runner::prepare()` runs at `template_redirect` priority 0. Resolution requires
an existing published, non-password-protected, launchable Sprint with a valid
linear structure. Anonymous visitors receive a normal WordPress login redirect
with `Routes::url()` as the full return destination. The authenticated identity
always comes from `get_current_user_id()`. AccessManager runs before any private
content filtering or progress operation. Unavailable content returns 404, denied
access 403, and a ProgressService failure or unsafe current state 503. Errors
contain generic recovery/return guidance, without private titles or service detail.

For matched requests only, prepare removes normal canonical/old-slug redirects,
clears unrelated main-query context, sets status, hides the admin toolbar, and
sends private/no-store/no-cache and noindex headers. It defines DONOTCACHEPAGE.
An upstream cache that serves before WordPress must separately bypass this route.
The plugin template replaces theme rendering via `template_include` priority 99.
Unrelated requests keep their normal query, template, title and asset behaviour.

Activation registers the route before flushing. Deactivation removes its
in-memory rule before flushing and preserves content/progress. There is no
runtime flush and no schema change. Existing active installations must save
Settings → Permalinks once after deployment, or deactivate/reactivate. Pretty
permalinks are required; plain/index.php permalink configurations are not a
separate supported Runner URL mode in this increment.

## Access API

`AccessProvider::can_access($user_id, $sprint_id)` is the internal contract.
`LoggedInAccessProvider` requires integer IDs, an existing authenticated current
WordPress user, and a valid Sprint. Publication/launch checks belong to Runner.

`AccessManager::__construct(?AccessProvider $provider = null)` accepts an injected
policy and defaults to LoggedInAccessProvider. `can_access($user_id, $sprint_id)`
delegates to it and returns the boolean result of:

```php
apply_filters('sprint_engine/user_can_access_sprint', $allowed, $user_id, $sprint_id);
```

The filter can grant or deny the provider decision. It cannot bypass Runner's
separate authentication/publication checks. No roles, commerce or entitlements
are added. Future callers must perform their own authentication before this
access-decision boundary, as Runner does.

## Runner methods and context

Runner constructor accepts optional AccessManager and ProgressService objects.
Its PHP-public integration/hook methods are `register_hooks()`, `resolve($slug)`,
`prepare()`, `template($template)`, `template_path($context)`, `enqueue()` and
`document_title($title)`. These are coordination methods, not HTTP endpoints.
Private helpers `content($post)` and `unavailable($status)` handle rendering and
safe error contexts. Routes exposes register/unregister, hook registration,
query/request filters, slug detection and canonical URL construction.

Successful context contains `state`, HTTP `status`, `sprint_id`, `title`,
`canonical_url`, `estimated_minutes` and the unchanged service `progress` array.

| State | Additional context and behaviour |
| --- | --- |
| `not_started` | `overview` is escaped/formatted excerpt or normally rendered Sprint content. Ready to start creates no enrolment or Step progress. |
| `in_progress` | Calls `resume_sprint()` after reading state. `step` contains canonical `id`, `title`, `stage`, rendered `content`; membership is rechecked and passwords are not bypassed. |
| `completed` | No Step object, reopen, restart or writes. The service supplies 100% progress and completion timestamp. |
| `login` | Only `state`, `status: 302`, `login_url`; prepare redirects and exits. |
| `error` | Only `state`, `status`, generic `message`; no private content/progress. |

Progress fields are the SE-003 status/Sprint/current Step IDs, completed/total
counts, percentage and UTC timestamps. The shell displays completed_steps,
total_steps and percentage without recalculation. Completion time is available
to replacement templates; the default shell does not display it.

The explicit resume operation preserves SE-003 activity and recovery semantics.
A stale current pointer can be repaired against an otherwise valid chain. A
broken chain must first be repaired through authoring; Runner never guesses an
order or modifies links. Completed history is preserved. Request-supplied user
and Step IDs do not select state or content.

Step eligibility follows the existing Meta/StructureManager/ProgressService
definition of valid assigned Steps, including draft Steps created by Quick Add.
Publishing and enabling the parent Sprint is the member release gate; authors
must review all assigned Step content before launch. No new Step publication
workflow is inferred by SE-004.

## Templates, blocks and assets

`template()` places authorized context in the internal `se_runner_context` query
variable. The default is `templates/runner.php`, using semantic headings, main,
article, skip link and an accessible native progress element. It never calls
theme get_header/get_footer. It uses wp_head/wp_body_open/wp_footer for normal
WordPress integration and supplies an explicit escaped document title.

`sprint_engine/runner_template` receives `(default_path, context)`. Replacement
must resolve to a readable PHP file under WP_PLUGIN_DIR, WPMU_PLUGIN_DIR or the
active theme root. Realpath checks prevent symlink escapes; wrappers, null bytes,
non-strings, missing paths, directories and non-PHP files fall back to the default.
This is a trusted PHP integration hook, not a request-controlled include API.

Content goes through `the_content` with temporarily established post globals,
restored in a finally block. Normal Gutenberg paragraphs, headings, lists and
native audio render through WordPress; there is no custom player. Titles,
metadata, links, progress and errors are escaped at output. Filtered content HTML
is intentionally retained, like normal WordPress content rendering.

Only matched frontend Runner requests enqueue `assets/css/runner.css`. CSS gives
a constrained readable width, responsive spacing, focus visibility, progress
and bounded block/media widths. No Runner JavaScript is added. wp_head/footer
may still carry theme/plugin enqueues; compatibility with the target theme and
plugins must be checked on the target host.
