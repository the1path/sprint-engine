# SE-009 — Final Authoring & Runner Polish

> Historical validation record: results, release stages and remaining checks below
> refer to this ticket at the time it was recorded. Core 0.2.0 is now released.

## Scope and decisions

The ticket explicitly supersedes the specification's example continuity wording:
the always-visible “Continue where you left off.” message and unused CSS selector
are removed. There is no replacement or session tracking. Current Step resolution,
resume, ProgressService, enrolments, REST contracts, AccessManager, ordering logic,
explicit next-Step navigation, lifecycle events, cache policy, fingerprints and
database/schema versions are unchanged. No migration or new endpoint is added.

## Authoring

The native **Sprint setup** metabox explains that main Sprint content is the
pre-start introduction, and the first Step normally starts the actual work.
It also documents the existing excerpt precedence without changing it. No separate
Welcome field/type or editor is introduced. Structure Manager repeats one short
guidance paragraph; its Quick Add/reorder behaviour is unchanged.

The non-blocking checklist uses saved content/excerpt (non-whitespace text after
stripping tags/entities), associated `Meta::steps`, `StructureManager::is_linear`,
existing Launchable metadata and WordPress publication status. It uses existing
Availability and Routes helpers for an available View Runner link. Save/reload
refreshes it; no wizard or additional validation model blocks saving.

Stage Label remains free text, with phase help and a ten-value HTML datalist:
Discover, Diagnose, Analyse, Decide, Design, Build, Implement, Review, Reflect,
Measure. These are suggestions, not stored presets or a taxonomy. An assigned,
valid parent is displayed on the Step editor with a native **← Back to Sprint**
link from `get_edit_post_link`; absent or invalid parents have no broken action.

## Completion configuration

Registered protected Sprint metadata, each defaulting to an empty string:

| Key | Handling |
| --- | --- |
| `_se_completion_message` | Plain multiline `sanitize_textarea_field` text |
| `_se_completion_cta_label` | Plain `sanitize_text_field` label |
| `_se_completion_cta_url` | Absolute HTTP(S) URL, `esc_url_raw`, parsed host and URL validation |

These fields reuse the existing metadata registration, editor REST authorization,
nonce/capability-protected metabox save and shared validation. Native metadata
REST exposes them only in administrator edit context; no member contract changes.
Invalid URLs become empty. Full internal or external web URLs are accepted without
an origin/domain allowlist; the editor explains the full-URL requirement.

Only authorized completed Runner context contains completion configuration. Plain
text is escaped before `wpautop`; no content filters, shortcodes, scripts, forms or
embeds execute. Blank text retains **You have completed this Sprint. Your progress
is saved.** Both valid label and URL are required for a primary CTA link. The
existing heading, secondary Return to site, 100% progress and completed state stay
intact. The CTA performs ordinary navigation without a progress write.

## Branding

The existing `sprint_engine_runner_branding` array gains `primary_text`, default
`''` = Automatic. Nonempty values must be six-digit hex colours, normalized to
lowercase. Invalid submitted values retain the previous safe value; invalid stored
values fall back to Automatic. Empty values explicitly clear the override.

`--se-on-primary` uses the custom colour or the unchanged SE-008 black/white WCAG
contrast calculation. Derived/secondary styling still uses the original algorithm.
The existing colour picker offers a Clear control and Automatic placeholder/help.
Preview updates immediately; its non-blocking warning additionally checks primary
text/background contrast against 4.5:1. Low contrast remains saveable. Reset still
deletes only the branding option.

## Native Step list

`Content\StepListAdmin` registers `manage_se_step_posts_columns`,
`manage_se_step_posts_custom_column`, `restrict_manage_posts`, `pre_get_posts`
and `disable_months_dropdown`. Title and Date remain, with Parent Sprint and Stage
inserted before Date. Parent titles use native edit links; missing parent/stage
values use an em dash.

The read-only `se_parent_sprint` dropdown validates a positive integer and an
existing editable `se_sprint`. Invalid input selects All Sprints. Filtering only
affects the administrator's main `edit-se_step` query, adding the `_se_sprint_id`
constraint with AND while preserving existing metadata conditions, search and
pagination. Frontend, secondary and other-post-type queries are unaffected. Only
`se_step` suppresses the month dropdown; the Date column is retained.

## Deferred product ideas

- Sprint Dashboard / Save & Exit destination: available, in-progress and completed
  Sprints; no dashboard or exit destination change now.
- Dashboard **Continue where you left off** CTA, appropriate to returning members.
- Richer block-based Start/Completion editing; existing native Start content is
  retained. Welcome/Finish remain Sprint-level screens, never locked fake Steps.
- Completion form/integration support: no shortcode execution, raw embeds,
  iframes/scripts, HubSpot, form-plugin or webhook integration. Use a CTA URL now.
- Configurable Stage presets; present datalist is only guidance.
- Sprint categories/collections, informed by future catalogue/dashboard needs.
- Future dedicated Steps/Builder UX; native columns/filter are the intentional
  intermediate solution. No new manager, branching, commerce or other subsystem.
