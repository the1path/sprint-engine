## Attempts, restart and isolation — PASS

The latest positive attempt number is canonical, independent of timestamps.
Enrolment primary `id` is `attempt_id`; both attempt fields are null before Start.
First Start creates Attempt 1. Repeated Start and Start after completion preserve
the same attempt. Every service Step find/create/complete/count operation passes
the current attempt number explicitly. Repository defaults preserve internal
Attempt-1 callers; no runtime service operation relies on that default.

`restart_sprint()` is separate from `start_sprint()`. It validates current
structure and launchability, serializes under the existing Sprint row lock and
allocates N+1 only when the latest attempt is completed. The new attempt starts
immediately at the first current Step with zero completions, own UTC timestamps
and null completion. Previous enrolments and Step progress remain unchanged.
Never-started / `not_started` restart is rejected. Active restart returns unchanged
canonical state, providing retry safety without an in-progress Start Over.

The **51-assertion attempt suite** proves Attempts 1/2/3, sequential numbering,
exact history preservation, per-attempt completion/retries, current-only stale
repair/resume, changed structure, earlier timestamps, independent users, rollback
of first-Step insert and failed commit, and committed lifecycle identities.
The **145-assertion progress suite** includes two independent PHP restart workers:
both receive the identical fresh Attempt 2, zero completions and one new row;
their combined events contain exactly one Sprint start and one first-Step start.
The previous completed enrolment is unchanged. This is SQLite contention evidence,
not a claim of MySQL/MariaDB execution.

Lifecycle signatures preserve leading arguments and append identity:

```text
sprint_engine/sprint_started(user_id, sprint_id, attempt_id, attempt_number)
sprint_engine/step_started(user_id, sprint_id, step_id, attempt_id, attempt_number)
sprint_engine/step_completed(user_id, sprint_id, step_id, attempt_id, attempt_number)
sprint_engine/sprint_completed(user_id, sprint_id, attempt_id, attempt_number)
```

Events run after successful commit only. Rollbacks and duplicate requests emit no
duplicate lifecycle events; listeners accepting fewer arguments remain compatible.
