## 1. Friendly generated usernames

Replace long random participant_ + 32 hex generated login with readable name-derived login for NEW native participant accounts only. Follow native WordPress sanitization/validation principles, inspired by WooCommerce but no Woo dependency, e.g. jane.smith, jane.smith.2, jane.smith.3. Use deterministic safe transliteration (native remove_accents and sanitize_user strict where appropriate), lowercase safe components, no spaces/markup, respect WP login 60-character limit including suffix, sensible handling of punctuation, one transliterable component, non-Latin/empty/unusable names. Fall back to a compact cryptographically random participant_ suffix (e.g. 8+ hex, justify entropy/collision handling); do not derive login from full email or email local part. Existing standard profile names/display name unchanged; email remains normal sign-in identifier, no additional username field or participant-visible username requirement. Never rename existing accounts or update/delete existing users, no migration.

Preserve all existing safety boundaries: generation and bounded uniqueness resolution within existing owned mutex/native account creation flow, validate candidate with native validation, use fresh authoritative case-insensitive database collision checks matching actual native collation, ensure suffix cannot exceed WP limits, recheck before insertion, reject unexpected native filter modifications, never choose reserved/invalid candidates, cap work and use safe random fallback or safe failure rather than unbounded suffix scanning. Respect existing native username/email validation hooks and provider policies; don't retry to circumvent a denial. No claim of global uniqueness against independent native creators. Consider privacy implication of readable login being public author slug on ordinary WordPress; document that it derives from name, not email, and is not a secret. Keep password, identity receipt, authentication, lock/replay/state/transaction/generation and native closure architecture intact. Test actual collisions with existing ordinary/native/Woo users, case/diacritics, long names, duplicate name with distinct emails, Unicode-only names, suffix limit, invalid native usernames, independent concurrent submissions with same name and distinct email (within existing budget), duplicate email/replay and native hook denial; exact profile values preserved and existing users unchanged.
